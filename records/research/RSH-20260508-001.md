# RSH-20260508-001: Linux Web-Source Contract

## 1. Fetchers And Platform Gates

- Claude web fetcher: `Sources/CodexBarCore/Providers/Claude/ClaudeWeb/ClaudeWebAPIFetcher.swift`.
- Claude macOS path uses SweetCookieKit only for browser cookie acquisition. All Claude API calls are plain HTTP once the `sessionKey` cookie is known.
- Claude Linux path currently falls into `#else` stubs that throw `FetchError.notSupportedOnThisPlatform`.
- Codex web fetcher: `Sources/CodexBarCore/Providers/Codex/CodexWebDashboardStrategy.swift`, with helpers under `Sources/CodexBarCore/OpenAIWeb/`.
- Codex macOS path imports cookies into a WebKit `WKWebsiteDataStore`, validates the signed-in account, scrapes the dashboard SPA, and also preflights the direct `chatgpt.com/backend-api/wham/usage` JSON endpoint.
- Codex Linux path currently exposes an unavailable `CodexWebDashboardStrategy` stub.
- `ProviderFetchPlan` resolves executable strategies per provider and source mode. Claude and Codex both advertise `.auto`, `.web`, `.cli`, and `.oauth`. CLI runtime prefers web first for `codex --source auto` and uses Claude's planner for Claude source ordering.

## 2. Cookie Contracts

- Claude requires a cookie named `sessionKey` for domain `claude.ai`.
- Claude `sessionKey` values are expected to be non-empty and start with `sk-ant-`.
- Claude sends the cookie as `Cookie: sessionKey=<value>`.
- Codex/OpenAI web requires authenticated ChatGPT cookies for domains `chatgpt.com` and `openai.com`.
- Codex session detection treats cookie names containing `session-token`, `authjs`, or `next-auth` as session cookies; `_account` is also a positive signal.
- Codex direct API calls can use a normal Cookie header assembled from matching `chatgpt.com` cookies.

## 3. HTTP Contracts

- Claude organization endpoint: `GET https://claude.ai/api/organizations`.
- Claude organization response shape: JSON array of organizations with `uuid`, optional `name`, and optional `capabilities`; the fetcher prefers an organization with `chat` capability, then non-API-only, then first.
- Claude usage endpoint: `GET https://claude.ai/api/organizations/{org_id}/usage`.
- Claude usage response shape includes `five_hour.utilization`, `five_hour.resets_at`, optional `seven_day.utilization`, optional `seven_day.resets_at`, and optional `seven_day_sonnet` or `seven_day_opus` utilization.
- Claude extra endpoint: `GET https://claude.ai/api/organizations/{org_id}/overage_spend_limit`.
- Claude account endpoint: `GET https://claude.ai/api/account`, used best-effort for email and plan metadata.
- Claude auth scheme: cookie auth only, `Cookie: sessionKey=<sessionKey>`, `Accept: application/json`.
- Codex usage endpoint: `GET https://chatgpt.com/backend-api/wham/usage`.
- Codex identity endpoints: `GET https://chatgpt.com/backend-api/me` and `GET https://chatgpt.com/api/auth/session`.
- Codex usage response shape decodes as `CodexUsageResponse`: `plan_type`, `rate_limit.primary_window`, `rate_limit.secondary_window`, and optional `credits.balance`.
- Codex auth scheme: browser Cookie header, `Accept: application/json`, `Accept-Language: en-US,en;q=0.9`, and a `CodexBar` user agent.

## 4. Linux Browser Cookie Locations

- Chrome: `~/.config/google-chrome/<profile>/Cookies` and `~/.config/google-chrome/<profile>/Network/Cookies`.
- Chromium: `~/.config/chromium/<profile>/Cookies` and `~/.config/chromium/<profile>/Network/Cookies`.
- Microsoft Edge: `~/.config/microsoft-edge/<profile>/Cookies` and `~/.config/microsoft-edge/<profile>/Network/Cookies`.
- Common Chromium profile names include `Default`, `Profile *`, and `Guest Profile`.
- Chrome Flatpak: `~/.var/app/com.google.Chrome/config/google-chrome/<profile>/Cookies` and `Network/Cookies`.
- Chromium Flatpak: `~/.var/app/org.chromium.Chromium/config/chromium/<profile>/Cookies` and `Network/Cookies`.
- Edge Flatpak: `~/.var/app/com.microsoft.Edge/config/microsoft-edge/<profile>/Cookies` and `Network/Cookies`.
- Firefox profiles are discovered from `~/.mozilla/firefox/profiles.ini`; the selected profile contains `cookies.sqlite`.
- Firefox Flatpak profiles are under `~/.var/app/org.mozilla.firefox/.mozilla/firefox/profiles.ini`.

## 5. Chrome Cookie Encryption On Linux

- Chromium cookie rows have `value` and `encrypted_value`. When `value` is non-empty, it can be used directly.
- Encrypted rows commonly start with `v10` or `v11`.
- Chromium's Linux secret is normally obtained from libsecret. A practical non-interactive probe is `secret-tool lookup application chromium`, with browser-specific variants as fallback.
- `--password-store=basic` commonly falls back to the historical `peanuts` secret.
- Newer Chromium profiles may expose `os_crypt.encrypted_key` in `Local State`; implementations should base64-decode it and try it as a raw key when libsecret lookup fails.
- Decryption failures must be warnings, not fatal errors. The reader should return plaintext cookies and any successfully decrypted cookies.

## 6. Implementation Recommendation

- Implement Claude first because its web path is already HTTP-only after `sessionKey` acquisition.
- Implement Codex second by using the direct `backend-api/wham/usage` and identity APIs on Linux. Full WebKit dashboard scraping remains macOS-only, but the direct usage endpoint is enough for top-bar usage.
- Keep all Linux cookie-reader code in `Sources/CodexBarCore/CookieReading/` behind `#if os(Linux)`.
